High-Scale Flash Sale Reservation Architecture (SKIP LOCKED)

Traditional row updates (UPDATE items SET qty = qty - 1 WHERE sku = 'HOT-SKU') fail under peak flash sales because thousands of concurrent checkouts block each other on a single database row lock, causing database connection exhaustion and lock wait timeouts.
This service represents available units as individual rows inside a bounded pool and selects units atomically using FOR UPDATE SKIP LOCKED. Concurrent checkouts skip locked units and lock free units in parallel with sub-millisecond hold times!
